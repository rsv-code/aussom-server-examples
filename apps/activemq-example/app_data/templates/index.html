ActiveMQ Example App

About:

This app is a working round-trip example of the activemq apac module and the Aussom Server Client Listener feature. It runs an embedded Apache ActiveMQ broker inside the server's JVM, publishes a made-up order record to a queue when you call an HTTP endpoint, and lets a registered ActiveMqListener pick the message up and process it on a server-managed background thread. You then read the results back over HTTP.

Definition: Generated OAS Specification for the activemqexample API

How It Works:

  1. At app start, the constructor starts an embedded in-memory ActiveMQ broker (vm://activemqexample), opens one shared publisher connection, and registers an ActiveMqListener on the orders.example queue with app.registerListener(). The server runtime owns the listener's thread and lifecycle.
  2. GET /activemqexample/publish builds a made-up order record, opens a short-lived session and producer from the shared connection (session-per-send, because JMS sessions are not thread-safe), and sends the record to the queue as a JSON text message.
  3. The listener receives the message on its own thread, parses the JSON back into a record, computes the order total, marks it processed, acknowledges the message, and stores the result.
  4. GET /activemqexample/status reports the listener's counters and the processed records, so you can confirm the full round trip.
HTTP request embedded broker listener thread | | | publish ---> orders.example queue ---> onOrder(msg) ---> processed list | | | status <----------------- shared app state <------------------+

The app also demonstrates the threading discipline a real server app should follow: HTTP handlers write no shared state (order IDs come from uuid.get()), and all counters and records are owned by the single listener thread.

Endpoint Info:

All endpoints are GET requests and return application/json unless noted. Try it from a terminal:

curl http://localhost:8081/activemqexample/publish
curl http://localhost:8081/activemqexample/status
GET /

HTML landing page (this page). Rendered with Handlebars from app_data/templates/index.html.

Returns: text/html

GET /publish

Builds a made-up order record and publishes it to the orders.example queue. The client listener picks it up from there. Call it as many times as you like; each call publishes one message.

Returns: the published record and the broker-assigned message ID.

{
  "published": {
    "orderId": "ORD-1f0c9a4e-...",
    "customer": "Sgt. Schultz",
    "item": "Apple Strudel",
    "quantity": 12,
    "unitPrice": 3.5,
    "status": "new"
  },
  "messageId": "ID:hostname-43210-1780724827122-4:1:1:1:1"
}
GET /status

Reports what the listener has processed. After a publish, the matching record shows up here with status flipped to processed and a computed total - that is the proof the message went through the broker and the listener handled it. The processed list holds the most recent 25 records.

Returns: listener counters and processed records.

{
  "processedCount": 1,
  "errorCount": 0,
  "lastError": "",
  "processed": [
    {
      "orderId": "ORD-1f0c9a4e-...",
      "customer": "Sgt. Schultz",
      "item": "Apple Strudel",
      "quantity": 12,
      "unitPrice": 3.5,
      "status": "processed",
      "total": 42.0,
      "brokerTimestamp": 1780724827122
    }
  ]
}
